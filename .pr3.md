## Summary

`docs/add-provider.md` states the contract as its first rule, and says these
are "all enforced in review":

> **Fail-open, never raise.** Wrap the whole body; every failure path returns
> `build_unavailable("<provider>", "<machine-readable-reason>")`.

Nine of fifteen registered fetchers did that. The other six — `grok`,
`antigravity`, `kimi`, `gemini`, `opencode-go`, `copilot` — could raise out of
the registered callable.

The sweep survived, because `quota_cache._fetch_one` catches. But the provider
then recorded the generic `fetch-error` instead of a reason of its own, which
the *next* rule also forbids:

> **`unavailable_reason` must be truthful.** `no-data`, `no-credentials`,
> `opt-in-disabled` mean different things to users staring at the muted card.

### Confirmed escapes

Run through the **registered** fetcher, not the inner function:

| Provider | Trigger | Escaped as |
| --- | --- | --- |
| `gemini` | DNS failure | `OSError` |
| `gemini` | `expiry_date: "soon"` | `ValueError` from `float(exp)` in `_valid_token` |
| `gemini` | tier probe times out | `TimeoutError` |
| `opencode-go` | 200 with `rate_limit: [...]` | `AttributeError` |
| `opencode-go` | 200 with `credits: [...]` | `AttributeError` |
| `opencode-go` | `reset_at: 1e18` | `OSError: Value too large` |

The gemini ones fire *before* any of its own error handling. The opencode-go
ones are structural: `_fetch_codex_with_models` closes its `try/except` at
`builtin.py:478` and then parses `rate_limit`, `rate_limit_reset_credits`,
`credits`, and each `additional_rate_limits[].rate_limit` with a bare `.get()`
chain.

## The fix

`register()` now wraps each fetcher, so the contract holds **at the seam**
rather than in fifteen bodies — and a provider added later inherits it without
having to remember.

```python
def _wrap(fn):
    @functools.wraps(fn)
    def _fail_open() -> QuotaResult:
        try:
            return fn()
        except Exception:
            return build_unavailable(provider_id, "fetch-error")
    PROVIDER_FETCHERS[provider_id] = _fail_open
    return fn
```

`functools.wraps` keeps `__name__`, so logs and tracebacks still name the
provider. The reason code stays `fetch-error`, so **no currently-correct
mapping changes** — this closes the escapes without altering any provider's
existing behaviour.

I chose the seam over hand-wrapping six bodies deliberately: the existing
per-provider handlers are readable and specific, and nesting a `try` around
each would obscure them for no gain.

### Targeted fixes alongside it

- **`gemini._post_json`** handled only `HTTPError`, so a `URLError` or
  `OSError` escaped. It now reports a transport error distinctly, and the
  fetcher returns `fetch-error` rather than the nonsensical `http-None`. It
  also closes the `HTTPError` handle, matching the pattern from `e56be7c`.
- **`gemini._valid_token`** tolerates a non-numeric `expiry_date`.
- **codex post-request parse** is shape-checked field by field, and `_iso`
  catches `OverflowError`/`OSError`/`ValueError` from an out-of-range
  timestamp.

## Two existing assertions I had to touch

`test_antigravity.RegistrationTests.test_provider_is_registered` and
`test_minimax.MiniMaxParseTests.test_registered` compared the registry entry by
**identity** (`assertIs(PROVIDER_FETCHERS["antigravity"], mod.fetch_antigravity_quota)`),
which is precisely what the wrapper changes.

Both are updated to compare against `__wrapped__`. Their stated intent —
antigravity's comment is *"Registered ungated, like every other provider
except grok"* — is unchanged and still asserted. No behavioural expectation was
weakened; only the identity check moved to the wrapped original.

## Tests

`tests/test_fail_open_contract.py` — **14 offline tests**. **11 fail on
`6852004`**, verified against unmodified upstream/master in a throwaway clone.

- every registered fetcher is wrapped, and a fetcher registered later inherits
  the guard
- the guard turns an exception into a `QuotaResult` and passes a normal result
  through untouched
- `functools.wraps` preserves the name
- the three gemini escapes, each driven through `PROVIDER_FETCHERS["gemini"]()`
  rather than the inner function, so the test exercises the real seam
- `_valid_token` tolerates five malformed `expiry_date` shapes
- `_post_json` distinguishes a transport error from an HTTP status
- the four codex post-request parse escapes, plus a well-formed payload that
  must still parse
- `add-provider.md` still states the rule, so it can't be quietly dropped
